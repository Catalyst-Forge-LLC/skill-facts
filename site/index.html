Why it exists

Skills are the plain-English supply chain. Almost nothing labels what they teach.

AppFacts labels the body. ModelFacts labels the brain. ToolFacts labels the toolbelt. AgentFacts labels the hands. SkillFacts labels the playbook: what installable instructions will teach an agent to do, in a file you can validate, diff, and review before install.

The boundary: ToolFacts labels an executable instrument. SkillFacts labels instructions an agent follows. AgentFacts labels an actor configuration. A skill can tell an agent to run scripts, fetch URLs, or move data. Facts about what a named tool does when run belong in ToolFacts; facts about what the host agent is permitted to do belong in AgentFacts.

The golden rule: if it's subjective ("great productivity skill") it doesn't belong here. If it's objective ("instructs the agent to run curl against an external host") it does. When a fact isn't public, the file says undisclosed.

  • Operators deciding whether to install a marketplace or repo skill
  • Teams reviewing shell, network, and filesystem reach implied by playbooks
  • Harnesses that need a structured surface before attaching skill packages
  • Anyone who wants skill teaching intent in a file they can CI-check

The format

Frontmatter you can validate. A label you can skim.

---
skill_facts_version: "0.1.0"
name: Docs Writer
developer: Catalyst Forge
version: "0.1.0"
status: active
license: Apache-2.0
kind: cursor-skill
purpose: Teach an agent to draft and revise project documentation in the repo voice
provenance:
  source: https://github.com/Catalyst-Forge-LLC/skill-facts
  publisher: Catalyst Forge
instructions_reach:
  shell: none
  network: none
  filesystem: read
tools_referenced: []
bundled_artifacts: []
egress:
  telemetry: none
  destinations: []
generated:
  date: 2026-08-07
  generator: hand-authored
---

Spec document 0.1.0 - fields may still shift before 1.0. Files declare skill_facts_version (0.1.0 today) so tooling can evolve with them. v0.1 covers cursor-skill, claude-skill, agents-skill, and other.

Validate one

Hand-author from the template today. The generator (parse SKILL.md and bundled scripts first, optional LLM classification last) is next; until then, the validator is the CI gate. 

# validate any SKILL_FACTS.md (CI-friendly exit codes)
cd skill-facts/validator && pnpm install
pnpm validate ../examples/docs-writer/SKILL_FACTS.md
pnpm validate ../examples/*/SKILL_FACTS.md
pnpm validate path/to/SKILL_FACTS.md

Frontmatter is checked against skill-facts.schema.json (draft-07). Prefer the harsher instructions_reach value when unsure, and human-review before publishing to a directory.
